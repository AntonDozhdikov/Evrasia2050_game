# «Евразия 2050» — передача в стадию 3

**Смысл:** публикация работоспособной браузерной исследовательской игры на сохраненных результатах второй стадии, а не очередное обучение MAPPO ради улучшения одних метрик.

## Неподлежащий изменению научный контракт
- История: официальная Stage1, 2000–2025, без синтетической подмены пробелов. Начальное состояние игры: 2024 год.
- Игровые переходы: 2025–2050. 8 стран: RUS, BLR, KAZ, KGZ, UZB, TJK, TKM, ARM.
- У агента 6 компонент действия по 3 уровня; пространства действий и подписей не менять без явной версии.
- Экономика V4.7: двустороннее согласие, финансовые ограничения, 2-летняя задержка отдачи, отказ от повторных проектов, отсутствие прямых наград за договоренности.
- 20 сценариев, 100 синтетических кризисных шаблонов.
- Набор стратегий: V4.7 MAPPO (обученная, детерминированная по умолчанию), V4.7 MAPPO stochastic (отдельно), V4.5 frozen (контроль), BARGAIN (правило), NEUTRAL (правило). Маркировать происхождение каждой.
- World Model использует инерционное решение по 8/8 целям; V4.1 — внешний исторический ориентир, не автоматическая подмена итоговых весов.

## Технический путь к первой рабочей игре
1. Реализовать на Python воспроизводимый эталон: `load_world_v44`, `load_marl_v44`, `EurasiaEnv`, симуляции и машинно-читаемые трассы для 2025–2050.
2. Зафиксировать протокол входа/выхода JSON: начальное состояние и маски, выбранные агенты и действия, кризисы, годовой переход, экономические показатели, проекты, переговоры, интерпретация.
3. Реализовать численный движок в JS/WASM или через серверную API. Локальный HTML без сервера *не способен* непосредственно запускать Python+Torch модели и Qwen.
4. Собрать UI: карта/сеть стран, переключение страны игрока, переговоры, бюджеты и соглашения, временная шкала 2025–2050, кризисные события, аналитические графики, экспорт CSV/JSON.
5. Провести парные тесты Python vs web для одинаковых входных состояний и заранее зафиксированных кризисных шоков. Не сравнивать только начальные числа: ГПСЧ Python и JS могут различаться.
6. Подключить Qwen3-4B + LoRA к серверному сервису либо документированным шаблонам (при недоступности сервиса), проверяя численную точность выдаваемой интерпретации.
7. Опубликовать HTML/JS пакет для обычного браузера (например, в Яндекс Object Storage) и архив проекта в облачном хранилище. Интерфейс: профессиональный, сдержанный, бело-сине-красные акценты.

## Критерии готовности стадии 3
- Игровой цикл выполняется в обычном браузере, без Colab и установки Python пользователем.
- Все 8 стран различимы, кризисы меняют состояние, действия влияют на наблюдаемые результаты, лог подписывается синтетическим происхождением.
- Численные показатели в браузере сверены с эталонной средой на контрольных векторах; ошибки/допуски документированы.
- Участник видит, что автономия с 0 проектами может оказаться оптимальной при текущей модели; игра не принуждает к интеграции.
- Встроены настройки сложности, справка о предположениях, сохранение и экспорт сессии; правила не меняются скрытно.
- Результаты трактуются как сценарные, не как научно подтвержденный прогноз до 2050 г.

## Содержимое пакета
`src/` — полный исходный программный контур V4.7; `runtime/world/` — сохраненные прогнозные веса и параметры; `runtime/policies/` — выбранная MAPPO, замороженная V4.5 и другие контрольные чекпоинты; `runtime/lora_*` — два LoRA; `runtime/metadata/` — кризисы/сценарии; `runtime/game_input_tables/` — выгрузка состояний и сети; `reports/` — независимые численные проверки и протокол приемки; `SHA256.json` — контрольные суммы файлов.
